ISOMORPH - PACKAGE AND INSTALL
==============================
Plain text, 79 columns.

After setup, Python finds isomorph the same way it finds MyHDL: pip
puts the package in site-packages. No PYTHONPATH, no sys.path
edits, no .bashrc hacks. A design file starts with the house
import and nothing else:

    from isomorph import (block, signal, signals, enum, always_ff,
        always_comb, assign, concat, replicate, bits, struct,
        attr, open_port, instances)

Python 3.11 or newer. pip. That is all.


1. TWO TREES
------------
  Development tree (git, tests, Quartus work):

    /home/<you>/.../isomorph          this repository

  Archive (one file, what colleagues get):

    isomorph-<version>.tar.gz

  Do not put RTL designs inside the unpacked archive. Keep designs
  in their own project directories.


2. MAKE THE ARCHIVE
-------------------
From the development tree:

    ./install.sh --tar

That writes isomorph-0.1.0.tar.gz into the current directory. It
unpacks to a single directory isomorph-0.1.0/ holding

    install.sh
    INSTALL.txt
    pyproject.toml
    SPEC.txt
    isomorph/                the Python package

Caches, egg-info and __pycache__ are left out. Somewhere else:

    ./install.sh --tar --dest /tmp

A plain directory instead of an archive, to scp or to keep:

    ./install.sh --pack                     copies to ~/isomorph
    ./install.sh --pack --dest /tmp/isomorph


3. GIVE IT TO A COLLEAGUE
-------------------------
On a machine with a network, one line does all of it:

    curl -fsSL \
    https://raw.githubusercontent.com/steve-groom/isomorph/main/install.sh \
    | sh

install.sh notices it has no tree around it, fetches one from
GitHub into a temporary directory, installs from that and deletes
it. Everything section 4 describes then happens as if they had
unpacked a tarball, the offer of external tools included, and the
prompts read from the terminal rather than from the pipe. Options
go after the pipe: `| sh -s -- --deps`.

The same in two steps, if they have pip already and want the
package alone:

    pip install git+https://github.com/steve-groom/isomorph
    isomorph doctor --install

pip clones and installs the package; install.sh never runs, so the
second line is what offers the external tools. It is the same code
install.sh calls.

Otherwise send them the one file:

    scp isomorph-0.1.0.tar.gz colleague:

pip installs from the unpacked tree; it does not download isomorph
from PyPI, so they must have the file on disk before they install.
This is the way in for a machine behind a firewall, or one that
must stay on a known version.


4. INSTALL (THEY RUN THIS)
--------------------------
    tar xzf isomorph-0.1.0.tar.gz
    cd isomorph-0.1.0
    ./install.sh

What that does:

  1. Runs:  python3 -m pip install --upgrade .
     If the active environment is not writable (no conda or venv
     write access) it retries with --user, and if the machine
     cannot reach PyPI for setuptools, once more with
     --no-build-isolation.
  2. Imports the house names from outside the unpacked tree and
     prints the installed file path, so the tree sitting in the
     current directory cannot answer for site-packages.
  3. Runs `isomorph doctor --install`, which reports which
     external tools the machine has and offers to install the
     missing ones (section 10). That needs root, so it asks first
     and does nothing unless the answer is yes. MyHDL leaves this
     to you; isomorph does not.

Where it lands:

    ./install.sh          the site-packages of the active python,
                          which is the directory MyHDL is in
    ./install.sh --user   the home one, ~/.local/lib/pythonX.Y
    ./install.sh --target ~/tools/isomorph      a folder of yours

The default is the MyHDL answer: pip puts the package in the
site-packages of whichever python is active, so a conda or venv
install lands beside myhdl in that environment and a design file
imports both the same way. `--user` is the fallback when that
directory is not writable, and Python searches it already.

`--target DIR` puts the package where you say instead, for a tools
folder kept outside any environment. It writes one line into
site-packages, isomorph.pth, holding that directory; Python reads
.pth files at startup, so the import still needs no PYTHONPATH and
nothing in .bashrc. install.sh prints the path of that line.

The last thing install.sh prints is where isomorph ended up and,
if the machine has MyHDL, where that is, so the two can be read
side by side.

    ./install.sh --deps       install the tools without asking
    ./install.sh --no-deps    report them and never ask
    PYTHON=/path/to/python3.12 ./install.sh       a chosen one

Developers who want the install to track the files on disk:

    ./install.sh --editable

The unpacked directory can be deleted afterwards; the package is
in site-packages. Keep it if you want SPEC.txt to hand.


5. CHECK
--------
In a new shell (so you are not sitting on an old PYTHONPATH):

    python3 -c "import isomorph; print(isomorph.__file__)"

You should see either:

    .../site-packages/isomorph/__init__.py
    ~/.local/lib/pythonX.Y/site-packages/isomorph/__init__.py

not a stray copy on PYTHONPATH. Then:

    python3 -c "from isomorph import block, signal, always_ff"

Convert:

    python3 -m isomorph design.py
    python3 -m isomorph design.py --sv --vhdl --c99
    python3 -m isomorph dump design.py


6. WRITE A DESIGN
-----------------
A design file design.py in any directory. Three parts: the block,
a test bench that drives a simulator, and the main block that
builds the ports.

    from isomorph import (block, signal, signals, enum, always_ff,
        always_comb, assign, concat, replicate, bits, struct,
        attr, open_port, instances, main)

    @block
    def add2 (i_a, i_b, o_sum, WIDTH = 4):
        @always_comb
        def sum_comb ():
            o_sum.next = (i_a + i_b)[WIDTH-1:0]
        return instances()

    def test_add2 (sim):
        for a in range(16):
            for b in range(16):
                sim.set('i_a', a)
                sim.set('i_b', b)
                assert sim.get('o_sum') == (a + b) % 16

    if (__name__ == '__main__'):
        import sys
        design = add2(i_a = signal(4), i_b = signal(4),
                      o_sum = signal(4))
        sys.exit(main(design, test_add2))

The ports are built in one place, so the test bench and the
conversion can never drift apart. main() gives the file a command
line:

    python3 design.py                 run the test bench (Python)
    python3 design.py --run c99       run it through gcc
    python3 design.py --run verilator run it under Verilator
    python3 design.py --sv --vhdl     write the HDL
    python3 design.py --sv --lint     write it and check it
    python3 design.py --vcd wave.vcd  run and record a waveform
    python3 design.py --help          the full list

Three simulators, one test bench:

  python     interprets the IR. Slowest. print() and pdb work, so
             this is the one to debug in.
  c99        the emitted C99 through gcc, driven by ctypes. Fast.
             Signals wider than 64 bits are not supported.
  verilator  the emitted SystemVerilog under Verilator. This is the
             reference: if it disagrees with the other two, they are
             wrong. Reaches top-level ports only.

A design with no test bench still gets the writing half:

    main(design)

7. UPDATE
---------
You (maintainer): change the development tree, then

    ./install.sh --tar

They: unpack the new archive and run ./install.sh in it again.
pip --upgrade replaces the previous install.


8. UNINSTALL
------------
    python3 -m pip uninstall isomorph

Deleting the unpacked archive does not uninstall the package; run
pip uninstall as well.

A --target install is not recorded in pip's database, so pip will
not find it. Remove the two things it wrote:

    rm -rf DIR/isomorph DIR/isomorph-*.dist-info
    rm <site-packages>/isomorph.pth


9. IF IMPORT FAILS
------------------
  - python3 -c "import sys; print(sys.executable)"
    install.sh used a different python than the one you run.
    PYTHON=/the/right/python ./install.sh
  - python3 -c "import isomorph; print(isomorph.__file__)"
    If this is an old tree, unset PYTHONPATH. Isomorph must
    come from site-packages after a colleague install.
  - pip too old:  python3 -m pip install --upgrade pip
    then ./install.sh again.
  - Permission error on site-packages:  ./install.sh --user


10. EXTERNAL TOOLS
------------------
Isomorph converts to SystemVerilog and VHDL, and runs the Python
simulator, on a machine with nothing but Python installed. The rest
is optional and each piece switches on one feature:

    gcc        the c99 simulator backend, and compiling emitted C99
    g++        the verilator simulator backend
    make       building the Verilator model
    verilator  --lint of SystemVerilog, the verilator backend
    ghdl       --lint of VHDL, and running the emitted VHDL against
               the reference every cycle
    yosys      reading both emitted languages into one netlist
    yosys ghdl plugin
               what lets yosys read the VHDL half, so the two can be
               proved equivalent rather than only compared on the
               stimulus a bench happened to apply

On Debian and Ubuntu that is

    sudo apt-get install -y build-essential verilator ghdl yosys \
        yosys-plugin-ghdl

and ./install.sh --deps runs the right one for the platform it finds.


10.1 THE ONE QUIRK, ON DEBIAN AND UBUNTU
----------------------------------------
The packaged yosys-plugin-ghdl is built against GHDL's gcc backend
and the packaged ghdl is the llvm one, so the plugin looks for the
compiled IEEE libraries in a directory that does not exist and says

    warning: ieee library directory '/usr/lib/ghdl/gcc/vhdl/ieee/v08/'
             not found
    error: cannot find "std" library

The libraries are there, under the other backend's name. Point at them
and it works:

    export GHDL_PREFIX=/usr/lib/ghdl/llvm/vhdl
    yosys -m ghdl -p "ghdl --std=08 build/thing/thing.vhd -e thing"

Isomorph's own equivalence tests find that directory themselves, by
looking for the one with ieee/v08 under it, so nothing has to be set
for `python3 -m pytest` to work. This is only for driving yosys by
hand.

Ask what this machine has:

    python3 -m isomorph doctor

It prints one line per tool and, if any are missing, the exact
command to install them for the platform it detects (apt-get, dnf,
pacman or brew). To act on that:

    python3 -m isomorph doctor --install        asks first
    python3 -m isomorph doctor --install --yes  does not ask

Installing compilers needs root and is the machine owner's
decision, so it is always opt in. --install with no terminal to
ask at prints the command and installs nothing, rather than
guessing at consent. ./install.sh --deps is the same thing at
install time.

Nothing external is required, so doctor exits 0 with tools missing.
It exits 1 only if Python itself is too old, which is 3.11, or if
--install was asked for and could not be done.
